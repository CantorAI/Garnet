Native primary BF16 block storage: design after WS36 CPU feasibility
Status: DESIGN ONLY. GPU implementation, FP32 equivalence, memory and speed are unproven.

Evidence and distinction
WS35 observed graphics dirty accounting dominate approximately18GB Cantor footprint. WS36 checked every bit of all446actual BF16 weight buffers:11,850,481,664original bytes,9,078,100,992primary encoded bytes,9,083,469,824page-rounded estimate. These counts exclude other model memory and do not predict latency. Earlier coalesced native code retained masters/interleaved/compact copies; shared-half storage changed MPS reduction ordering and failed strict state equivalence/performance. Preserve those decisions.

Storage contract
Each block is four output rows by128K, in K-major/four-row order. A compact block stores512sign/mantissa bytes and256exponent-tag bytes; a raw block stores1024interleaved BF16 bytes. An8byte metadata value stores a256-byte-unit payload offset, one compact flag and8bit exponent base. Compact admission requires exponent range<=15. All finite BF16 values, signed zero and subnormals reconstruct exactly. No rounding, quantization, reduced context or precision change.

Initial GPU admission should use rows>256, rows divisible by4 and K divisible by128, normal BF16 projections without incompatible auxiliary layouts. This covers398actual buffers,11,842,617,344original bytes. Their codec payload+metadata is9,072,073,984bytes;48small matrices/7,864,320original bytes remain raw. Total planned BF16 primary bytes are9,079,938,304, before actual Metal allocation rounding. Unsupported/F32/non-saving inputs retain their original single representation. Do not silently keep an original full BF16 or interleaved duplicate after packed admission.

Ownership and failure
Add default-OFF Metal-only capability; preserve CUDA. A packed MetalBF16Weight::Impl owns one immutable payload and one metadata buffer, dimensions/device and original-byte accounting. BuildShared copies the existing shared owner, not bytes. Allocate only the selected representation, charge counters after both allocations succeed and undo exactly on destruction/failure. A failed second allocation releases the first; no partial ready object, raw-plus-packed fallback or leaked accounting. Retain owners through all GPU commands and existing Abort/Submit/rebuild/Close paths. Check all offsets, tensor products, metadata sizes and device buffer limits before allocation. No persisted packed cache in the first implementation; native packing/init/transient-memory costs must be recorded.

Execution and arithmetic
Use packed load helpers before existing FP32 math. Preserve original activation loads, K order, FP32 accumulation statements, SIMD reductions, group sizes, specialization constants and compile math settings. Keep four-output decode grouping; do not reuse the rejected eight-output variant. Implement original generic decode, large body-shape decode, vocabulary-head decode and FP32 BF16-tile prefill with the same operations and shared tile geometry. A packed weight must never reach a raw-only kernel. Incompatible optional exact-half/interleaved/screened/fused policies should fail configuration or retain the original raw representation before admission, rather than rematerializing a hidden full master. Original public generic/F32/mixed-graph fallbacks remain.

Separate raw/packed body-shape pipeline cache entries so equal dimensions cannot select a pipeline expecting a different weight argument type. Prepare bounded packed pipelines during initialization. Verify required threads/shared memory are supported; do not alter dispatch policy based on favorable timing. Keep original shape/ownership/pending-output/control validation and recovery semantics.

Telemetry
Expose allocated original/payload/metadata/live-owner counts and cumulative encoded packed-decode/prefill/head dispatch counts. If global counters are used, snapshot before/after the already serialized native infer request. Count actual supplied graph/head execution, not cached Build lists. Mark encoded counts as not completed-GPU counts and never derive native step counts from generated-token counts. Inventory both packed buffers with opaque IDs and explicit representation names; shared owners deduplicate globally. Original resource snapshots and TTFT/total/derived-decode accounting remain.

Validation before performance
Run CPU codec/metadata bounds and actual trained checkpoint checks; verify GPU reconstructed original BF16/FP32 bits including compact/raw mixtures and finite edge cases. Preserve current complete primitive FP32 output-word and FP64-envelope gates at actual4B/1.7B dimensions, B1/B2, raw/F32 fallback, generic/specialized/prefill/head paths and tail/invalid/uninitialized/pending/Abort cases. Test actual supplied alternate graphs/head, shared-owner closure, partial allocation failure and independent sessions. Require all32VLM/28text finite states/token IDs, image embeddings, prefix cold/warm and capacity error recovery to match accepted controls. CPU bit reconstruction alone cannot satisfy this.

Tradeoffs and uncertainties
Extra metadata loads, integer reconstruction, branches and changed register/cache behavior may slow decode/prefill despite fewer bytes. Native packing adds initialization and transient host memory; no speed claim from CPU counts, small-model old reports or component arithmetic. Actual Metal sizes, graphics dirty/process footprint and whole-system latency require measurement. No physical-per-buffer, clock/thermal or compression-caused performance attribution is established.
